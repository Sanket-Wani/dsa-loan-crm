# DSA Loan CRM

Production-oriented CRM and loan-operations platform for a DSA (Direct Selling Agent) business in India.
Covers the full lifecycle: lead acquisition → assignment → telecalling → qualification → follow-ups/meetings → handover → document collection/verification → eligibility → bank application/login → PD → legal/valuation → credit → in-principle sanction → final sanction → disbursement → post-sales.

> Status: **Milestone 1** — a genuine, database-backed working system (auth, RBAC, leads, telecalling, cases, documents, eligibility, bank applications/queries, master register, dashboards). Not a static dashboard.

## Stack & rationale
- **Next.js 14 (App Router) + TypeScript** — one modular monolith: UI + API routes, low ops overhead, easy hiring/maintenance.
- **PostgreSQL + Prisma** — relational data (leads/cases/bank applications), migrations, transactions.
- **Custom session auth** — bcryptjs password hashing (cost 12), signed JWT in an httpOnly cookie via `jose`. No bank passwords/OTPs are ever stored.
- **Server-side RBAC** — permission matrix in `src/lib/rbac.ts`, enforced in every API route plus object-level checks (telecallers only see assigned leads; back-office only own cases). Hiding a button is never the security boundary.
- **Zod** validation on API inputs · **Tailwind CSS** design system · **Vitest** unit tests · **ESLint**.

## Local setup
```bash
cp .env.example .env          # adjust SESSION_SECRET (long random string)
docker compose up -d          # PostgreSQL 16 on localhost:5432
npm install
npx prisma generate
npx prisma migrate dev --name init   # creates the first migration from prisma/schema.prisma
npm run db:seed               # dev-only demo data
npm run dev                   # http://localhost:3000
```

## Key modules
- `src/lib/rbac.ts` — permission matrix + object-level access (unit-tested)
- `src/lib/csv.ts`, `src/lib/duplicates.ts` — CSV import validation, per-row error report, phone/email duplicate detection
- `src/lib/eligibility.ts` — transparent arithmetic on reviewer-supplied inputs only. **No bank policy/formula is invented**; thresholds are reviewer-configured, a human decides.
- `src/lib/storage.ts` — document storage abstraction (metadata in DB; local dev driver; plug private S3 in production). Uploaded files are never committed.
- API: `/api/leads` (+`/assign`, `/import`), `/api/calls`, `/api/followups` (`?when=overdue|upcoming`), `/api/meetings`, `/api/handovers`, `/api/customers`, `/api/cases`, `/api/documents` (+`/checklist`, `/upload-metadata`), `/api/eligibility`, `/api/banks`, `/api/bank-applications`, `/api/bank-queries`, `/api/tasks`, `/api/register` (+`/export` CSV), `/api/dashboard`, `/api/employees`, `/api/products`.
- Master register is derived live from `BankApplication ⋈ LoanCase ⋈ Customer/Bank` with the exact columns: Login Date, Company Name, Client Name, Product, Status, Bank Name, Bank Manager / Consultant, Office Sales, Employee Code, Reference / Telecaller, Remarks, Sanctioned Loan Amount, Disbursed Loan Amount.

## Deployment notes
- Set `DATABASE_URL`, a strong `SESSION_SECRET`, `NODE_ENV=production` (enables Secure cookies).
- Run `npx prisma migrate deploy` in the release step, then `npm run build && npm start` (or containerise the same commands).
- Put the app behind HTTPS (encryption in transit); use managed Postgres with automated backups and point-in-time recovery; restrict DB network access (least privilege).
- Configure private object storage via the storage abstraction before handling real customer documents; enable the provider's at-rest encryption.
- Rotate/remove all seed users before go-live.

## Known limitations / next milestone
- Document upload stores **metadata only** in this milestone; binary upload through the storage driver is the next step.
- No live telephony, WhatsApp/Email/SMS sending, or AI call-analysis execution — only integration interfaces/foundations (`CallAnalysisRecord`, `Notification` models; see `docs/ARCHITECTURE.md`). Nothing external is sent and no third-party costs are incurred.
- First Prisma migration is generated by the documented `prisma migrate dev` step against your local Postgres; schema is committed, migration history starts in your environment.
- Excel (.xlsx) import/export: CSV is implemented; add SheetJS in a later milestone for native xlsx.

See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for modules, data model, RBAC and integration interfaces.
